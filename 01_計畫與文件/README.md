## 5. 必守規則

1. **個資**：
   - `IMG_original/` 與 `03_資料/01_原始封存/` 含姓名、病歷號。程式不顯示、不上傳、不外流原始影像。
   - 唯一例外是醫師圈選時勾選「匯出原始影像」：需要確認文字、寫稽核、只存受限區（D17）。
   - 開發與測試只用程式產生的合成影像；真實資料只做唯讀的數字檢查。
2. **答案不能進模型**：資料夾名稱與檔名前綴的 eGFR 只在匯入與對照時使用；API 只回傳 eGFR 分組。
3. **不登入**：以本機工作階段與「操作者名單」識別使用者；重要操作寫稽核紀錄。
4. **刪除**：研究資料先移入回收桶（可還原），永久刪除要輸入「永久刪除」。例外：任務紀錄可以直接永久刪除。
5. **所有模型重新訓練**，不使用舊專案的權重（ImageNet 公開權重可以用）。
6. **固定測試集只用一次**（M2.5 起依任務各自鎖定）。
7. **路由要登記**：新增 API 前綴要加到 `core/routes_table.py`。
8. **文件要跟上**：見 §7。

## 6. 怎麼啟動、測試、建置

| 目的 | 指令或作法 |
|---|---|
| 第一次安裝 | 執行根目錄的 `setup.bat`（需要 Python 3.12 與 Node.js 20＋pnpm） |
| 啟動 | `start.bat`（後端 127.0.0.1:8000，同時提供前端並開啟瀏覽器） |
| 停止 | `stop.bat` |
| 完整備份 | `backup.bat` |
| 後端測試 | `02_程式碼/backend/.venv/Scripts/python -m pytest`（在 `02_程式碼/backend` 執行） |
| 前端開發 | 在 `02_程式碼/frontend` 執行 `pnpm dev`（5173 埠，API 轉到 8000） |
| 前端型別檢查與建置 | `pnpm exec tsc --noEmit`、`pnpm build`（建置結果在 `dist/`，由後端提供） |

注意：系統內建的 `python` 指令可能是 Windows 的捷徑，請一律用 `.venv` 裡的 Python。

## 9. 名詞表

| 名詞 | 意思 |
|---|---|
| 去識別化影像 | 遮掉標頭個資、修補量測游標後的影像；分「模型用」「計算用」「縮圖」三種 |
| 體表示意圖 | 影像右下角的小人體圖，用來判斷左右腎 |
| 病人層級切分 | 同一位病人的影像只會在同一組（某一折或測試集） |
| 折（fold）、OOF | 交叉驗證把開發集分成 5 折；OOF（out-of-fold）預測是每張影像由「沒看過它那一折」的模型預測的結果 |
| 固定測試集、測試鎖 | 最後才評估一次的病人；評估過就鎖定，不能再評估 |
| 主切分 | 系統設定中指定的切分，圈選批次、遮罩組、比較組預設使用（M2.5） |
| 部分標註 | 一份遮罩不一定畫了所有構造；沒標的構造在訓練時忽略，不當成背景 |
| 構造狀態 | 每個構造是「已畫」「不在影像中」或「未標」 |
| 醫師圈選、比對差異法 | 醫師在系統外的圖上用顏色圈選；系統把傳回的圖和原本的影像逐像素比對，只取出新加的筆畫 |
| 顏色對照 | 設定每種筆的顏色代表哪個構造 |
| 圈選批次 | 一次交給醫師的一組影像（測試集，或每批約 100 張的訓練影像） |
| 學習曲線 | 分割模型的交叉驗證 Dice 隨累積張數的變化，用來決定何時停止圈選 |
| 交叉預測、遮罩組 | 用分割模型替全部影像預測遮罩；每位病人只用沒看過他的那一折模型（測試病人用 5 折平均） |
| 比較組 | 一次建立的一組 eGFR 模型（勾選的輸入方式 × 類別數） |
| 輸入方式 ①–⑥ | ① 影像 ② 影像＋臨床 ③ 純臨床 ④ 影像＋遮罩通道 ⑤ 影像＋遮罩量測 ⑥ 純遮罩量測 |
| 臨床資料 | 糖尿病、年齡、性別 |
| CORN、CORAL、CE、SORD | 處理有順序類別（例如 Grade 0–3、eGFR 分期）的輸出層與損失函數 |
