## 3. 連線與安全【已實作】

### 3.1 本機工作階段（不登入，決策 D12（改））

1. 前端開啟時呼叫 `GET /api/session/challenge`（需要標頭 `X-Local-Init: 1`），取得一次性挑戰碼（120 秒過期）。
2. 前端用挑戰碼呼叫 `POST /api/session`，取得工作階段 cookie 與 CSRF token；每分鐘最多建立 30 次。
3. 工作階段綁定伺服器的 `boot_id`，伺服器重啟後全部失效，前端會自動重建。
4. 只接受本機來源（`LOCAL_ONLY`）與本系統網頁的 Origin（`ORIGIN_REJECTED`）。

### 3.2 中介層（`app/main.py` 的 `guard`）

對每個 `/api` 請求依序檢查：
1. 公開路由（`/api/health`、`/api/session/challenge`、`POST /api/session`）直接放行。
2. 路由必須登記在 `core/routes_table.py` 的前綴清單，否則回 403 `API_NOT_REGISTERED`。新增 API 前綴時一定要登記；`tests/test_core.py::test_every_api_route_is_registered` 會檢查。
3. 必須有有效的工作階段，否則回 401。
4. 非 GET 的請求必須帶 `X-CSRF-Token`，否則回 403。
5. 回應加上 `Cache-Control: no-store` 與 `X-Request-ID`。

沒有角色與權限；所有使用者都能做所有操作，重要操作寫入稽核紀錄。

### 3.3 操作者

- 右上角從「操作者名單」選人，存在瀏覽器的 localStorage（`kidney-operator`），每個請求以 `X-Operator` 標頭（URL 編碼）送出；沒選時為「本機」（`app/api/deps.py`）。
- 存遮罩、確認或退回草稿必須真的選人。
- 回音分級另外在編輯器中選「判讀醫師」（醫師名單），寫入 `grade_labels.rater`。
- M2.5 起，醫師在系統外圈選，遮罩不記醫師身分，只記選填的圈選者代號（決策 D18）。

### 3.4 個資保護

- `IMG_original/` 與 `03_資料/01_原始封存/` 是受限區：API 永遠不提供原始影像，`GET /api/images/{image_id}/file` 只給去識別化影像。
- 標頭中的姓名、病歷號只在記憶體中處理：OCR 只回傳解析後的年齡、性別、量測值；病人對照時的病歷號分組也只在記憶體中（M2 #61）。
- 匯入後在去識別化影像上再跑一次 OCR，找個資殘留（設定 `residual_check`，每張都檢查，不是抽查）。
- API 不回傳 eGFR 數值，只回傳分組；標註畫面不含 eGFR 與臨床資料。
- **M2.5 例外【已實作】**：醫師圈選可勾選匯出原始超音波影像。需要確認文字、寫入稽核、只存到受限區 `01_原始封存/醫師圈選匯出/`；醫師傳回的原始影像只在記憶體中比對，存在受限區，網頁不顯示（決策 D17）。

## 4. 背景工作【已實作】

### 4.1 工作管理（`app/jobs/manager.py`）

- `JobManager` 有兩個執行池：
  - **CPU 執行池**：2 個執行緒（設定 `cpu_workers`，最多 4）。
  - **獨占執行池**：1 個執行緒。用 GPU 或大量記憶體的工作放這裡，一次只跑一個。
  - **醫師端執行池**：1 個執行緒（M3，D44）。`@register(..., pool='clinical')` 的工作放這裡，不排在幾小時的訓練後面。
- 工作用 `@register(種類, exclusive=, resumable=, label=)` 註冊；`get_manager().submit(種類, 設定, target=, created_by=)` 排入。
- 工作函式收到 `JobContext`：讀設定、回報進度與訊息、寫事件、檢查停止旗標。
- 停止：`POST /api/jobs/{job_id}/stop` 設定停止旗標，工作每秒檢查一次，結束後狀態為 `stopped`。
- 恢復：`resumable=True` 的工作可以 `POST /api/jobs/{job_id}/resume`，從中斷處繼續。
- 重試：建立新工作，`retry_of` 指向原工作。
- 伺服器重啟時：執行中的工作標成 `interrupted`，排隊中的重新排入。
- 進度：`GET /api/jobs/{job_id}`（前端每秒輪詢）；另有 SSE `GET /api/jobs/{job_id}/events`。
- 任務紀錄可以勾選後**永久刪除**（只限已結束的工作），這是回收桶原則的例外（M2 #77）。
- 工作結束後依序呼叫 `FINISH_HOOKS`（目前用來更新索引），失敗只記錄，不影響工作結果。
- 啟動時另外：建立缺少的 `說明.txt`、清除遮罩資料夾中的空資料夾、更新索引。

- `train` 工作建立子程序 `python -m app.ml.worker {RUN-ID}`，子程序呼叫 `engine.train_run`，輸出寫到 `train.log`。
- 每折的 `last.pth` 存完整狀態（模型、優化器、排程器、AMP、亂數產生器、早停計數），停止後可以恢復，結果和不中斷相同（`tests/test_training.py::test_engine_resume_matches_uninterrupted`）。
- 已完成的折有 `done.json`，恢復時會略過。
- 訓練結束後計算 OOF 預測、溫度校正與摘要，寫回 `training_runs.summary_json`。

## 5. 研究資料流程【已實作】

```
IMG_original／06_匯入區
   │ import：去識別化（遮蓋標頭、修補 caliper、扇形區外為 0）、OCR、體表示意圖判斷側別、像素間距
   ▼
images（usable／pending_review／excluded）── 版面範本、重新去識別化、重新判斷側別
   │ 病人表上傳 → 對照（eGFR＋OCR 年齡±1、性別；病歷號分組只在記憶體中）→ 人工確認／重新比對
   ▼
patients ──▶ splits（病人層級、依 eGFR 分組分層、測試集、各折、前瞻集；洩漏檢查）
   │
   ├─ 標註：醫師在系統外圈選 → 上傳 → 轉成遮罩（M2.5）；系統內編輯器只用來修正；回音分級（醫師盲測）；側別
   ▼
dataset_versions（凍結 manifest）
   │
   ├─▶ 訓練：分割（UNet／ResNet-UNet、nnU-Net 基準）、eGFR、回音分級
   │        → OOF 預測、溫度校正、交叉驗證評估、實驗比較
   ├─▶ 遮罩組：分割訓練交叉預測全部影像的遮罩（M2.5）
   ├─▶ 特徵：由遮罩、分割的 OOF 預測遮罩或遮罩組算回音與形態特徵
   ▼
models（模型庫）──▶ 固定測試集評估（只能一次）──▶ 一鍵流程／AI 分析
```

### 5.2 M2.5 新增的流程【已實作】

```
醫師圈選批次（測試集每側 1 張／訓練每批約 100 張）
   → 匯出（去識別化影像；可選原始影像）→ 醫師圈選 → 上傳 → 比對差異或標籤 PNG → 檢查 → 匯入成遮罩

   → 比較頁（配對 bootstrap）→ 一起評估固定測試集（eGFR 測試鎖）
```

## 6. 狀態機【已實作】

| 對象 | 狀態 | 轉換 |
|---|---|---|
| 影像 | `usable`、`pending_review`、`excluded` | 匯入時有疑慮 → `pending_review`；人工確認 → `usable` 或 `excluded`（需要原因） |
| 遮罩 | `draft`、`done`、`reviewed`、`rejected` | 存草稿 → `draft`；完成 → `done`；草稿被接受 → `reviewed`（記錄確認者）；草稿被退回 → `rejected`；任何版本都可以移入回收桶 |
| 訓練 | `draft`、`queued`、`running`、`completed`、`failed`、`stopped`、`interrupted` | 停止或中斷後可以從 checkpoint 恢復 |
| 模型階段 | `research` → `candidate` → `clinical` → `retired` | 升為 `clinical` 要輸入模型名稱並選核准醫師；同任務原本的臨床模型自動降為 `candidate`（M2.5 起 eGFR 只允許一個臨床模型） |
| 背景工作 | `queued`、`running`、`stopping`、`completed`、`failed`、`stopped`、`interrupted` | 見 §4.1 |
| 測試集 | 未鎖定 → 已鎖定（依任務） | 第一次固定測試集評估前就鎖定，失敗也不能重來。分割、eGFR、回音分級各自鎖定（決策 D27）；eGFR 由比較組一起評估、一次鎖定 |
| 圈選項目 | `pending` → `exported` → `parsed` → `imported`；或 `needs_redraw`（退回後下次匯出會再給醫師） | 【已實作】；轉換失敗時維持 `exported` 並記錄錯誤 |

## 7. 回收桶【已實作】

- 支援的物件：訓練（連同註冊的模型）、資料切分、資料集版本、遮罩（`app/trash/service.py` 的 `KINDS`）。訓練由訓練頁的勾選框移入（`POST /api/training/runs/trash`，M2.5 #109）。
- 刪除時先移入回收桶：物件標上 `trashed_at`，清單不再顯示；一組可以包含多個物件，整組還原。
- 永久刪除要輸入「永久刪除」，會移除資料列與檔案：訓練、評估、模型資料夾與分割的 OOF 預測遮罩（先刪評估、再刪模型、最後刪訓練，外鍵才不會擋）；切分檔；資料集版本資料夾；遮罩 PNG（並移除變空的分桶資料夾）。只刪物件自己的資料夾，`01_訓練紀錄/eGFR` 這類標準資料夾保留。
- 會檢查是否仍被引用：切分或資料集版本還被訓練使用、分割訓練還被遮罩組使用時拒絕（409），不會只刪一半；執行中的訓練、有臨床上線模型的訓練不能移入回收桶。
- 移入、還原、永久刪除後都會更新索引。
- 例外：任務紀錄是永久刪除，不經回收桶（M2 #77）。
