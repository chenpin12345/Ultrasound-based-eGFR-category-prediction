# 標註規範（草稿）

> 版本 v0.3（2026-11-06），草稿，待醫師確認。v0.1（2026-10-23）的作法是在系統內標註；依決策 D16–D21 改成**醫師在系統外圈選**；v0.3 依 D46–D51 改成**在獨立的「醫師圈選網站」圈選全部 975 張**。下面提到彩色圈選、顏色對照的段落，只適用於不用網站的舊流程。
> 文件導覽見 [README](README.md)。標有「待確認」的項目，必須在第一批圈選前由醫師決定，決定後寫入[決策紀錄](決策紀錄.md)。

## 1. 目的與分工

為重新訓練模型建立一致的答案：

- **分割模型**：腎臟（整顆腎外框）、腎竇、肝、脾。腎實質由程式計算（整顆腎扣掉腎竇）。
- **回音分級模型**：Grade 0–3（醫師在系統內盲測判讀，§4）。
- 影像品質不再標註（決策 D25）；不能用的影像在系統中「排除」並寫原因。

| 工作 | 誰做 | 在哪裡 |
|---|---|---|
| 選出要圈選的影像、匯出 | 你（專案負責人） | 系統「標註與回饋 › 醫師圈選」 |
| 圈選腎臟外框、腎竇、肝、脾 | 醫師 | 系統外（任何能在圖上用顏色畫線的工具，或標註軟體） |
| 上傳、檢查、匯入 | 你 | 系統「醫師圈選」 |
| 設定顏色代表什麼 | 你（看過醫師的圖之後） | 系統「設定 › 顏色對照」 |
| 回音分級 | 醫師 | 系統「標註與回饋 › 回音分級」 |
| 側別 | 系統依體表示意圖判斷，你確認 | 系統「資料集」 |

**用哪一份影像圈選**：
- 預設使用系統匯出的**去識別化影像**：沒有姓名、病歷號，量測游標已修補，檔名就是影像 ID。
- 可以另外勾選匯出**原始超音波影像**讓醫師挑選。原始影像上有個資，只能經醫院允許的管道傳送，需在 IRB 範圍內（決策 D8、D17）。
- 兩種影像的尺寸相同，醫師在任何一種上圈選都可以對回同一張影像。

## 1.1 醫師圈選網站（D46–D51）

- 主系統「醫師圈選」按「選取全部影像（圈選網站）」，匯出時勾選原始影像；網站「匯入影像」填這個受限資料夾。
- 醫師從頭圈選，沒有任何自動草稿。腎實質不用畫，由「整顆腎扣掉腎竇」算出。
- 項目（顏色可以改；醫師也可以新增顏色並定義意義）：

| 鍵 | 項目 | 預設顏色 | 傳回主系統 |
|---|---|---|---|
| 1 | 腎臟外框 | `#00E5FF` | 標籤 PNG（1，扣掉腎竇後是腎實質） |
| 2 | 腎竇 | `#FF4FD8` | 標籤 PNG（2） |
| 3 | 肝 | `#FFC400` | 標籤 PNG（3） |
| 4 | 脾 | `#7CFF4F` | 標籤 PNG（4） |
| 5 | 囊腫（水泡） | `#4D8DFF` | 只在 `圈選結果.json`；腎內囊腫仍在腎臟外框內 |
| 6 | 結石 | `#FF3B30` | 只在 `圈選結果.json`；圈結石本身，不含聲影 |
| 7 | 聲影／看不清 | `#FFFFFF` 虛線 | 只在 `圈選結果.json` |

- 基本四項沒圈時，要選「不在影像中」或「未標」；右腎影像的脾、左腎影像的肝預設「不在影像中」。按「完成」時，沒圈的其他項目記為「未見」。
- 回音分級每張一個（§4）。不能用的影像勾「影像不能用」並寫原因。
- 標籤 PNG 和畫面一致：像素中心落在圈選範圍內才算圈到。腎臟外框選「不在影像中」時不能圈腎竇。
- 輸出的 `標籤/`、`圈選結果.json`、`圈選結果.csv` 都不含影像內容。在主系統「上傳醫師圈選」填輸出資料夾路徑，狀態、圈選者、備註、回音分級會一起讀入。

## 2. 標註項目與標籤值

| 項目 | 醫師怎麼畫 | 匯入後的標籤值 | 筆的顏色 | 備註 |
|---|---|---|---|---|
| 腎臟（整顆腎外框，含腎竇） | 封閉輪廓 | 外框內、腎竇外為 1（腎實質） | **待定** | 程式計算：腎實質＝外框內扣掉腎竇 |
| 腎竇 | 封閉輪廓，畫在腎臟外框內 | 2 | **待定** | |
| 肝 | 封閉輪廓，圈看得到的整個肝（右腎影像） | 3 | **待定** | 決策 D19 |
| 脾 | 封閉輪廓，圈看得到的整個脾（左腎影像） | 4 | **待定** | 決策 D19 |
| 背景 | 不畫 | 0 | — | |

- **顏色先不決定**（決策 D21）：請醫師用不同顏色區分四種構造，並維持同一種畫法。你看過醫師的圖後，在系統「設定 › 顏色對照」指定每種顏色代表的構造；沒設定好之前，系統不會匯入彩色圈選。
- 「皮質」不另外畫：程式取腎實質中靠近腎被膜的外層帶當皮質（髓質錐體較暗，不能用整個腎實質），和實作一致（`features/service.py`）。
- 構造重疊時，系統依固定順序疊放：肝／脾 → 腎實質 → 腎竇。所以先畫哪一個都可以。

### 2.1 每個構造的狀態

匯入時，每個構造都有一個狀態，會影響訓練方式：

| 狀態 | 意思 | 訓練時 |
|---|---|---|
| 已畫 | 醫師有圈 | 當成答案 |
| 不在影像中 | 確定這張影像沒有這個構造 | 該區域可當背景 |
| 未標 | 沒有圈，也不確定是否存在 | **忽略**，不當成背景（部分標註） |

- 系統依側別自動設定：右腎影像的「脾」、左腎影像的「肝」為「不在影像中」。
- 其他沒圈到的構造預設「未標」；你在檢查時可以逐張改成「不在影像中」。
- 待確認：醫師要用什麼方式表示「這張沒有肝（或脾）」，例如在清單上註記，或畫一個小記號。

### 2.2 傳回檔案的格式

**彩色圈選**（直接在圖上畫）：
1. **檔名不能改**：系統依檔名（影像 ID）對應。
2. **尺寸不能縮放、不能裁切**：系統會檢查尺寸，不符的會列出原因並略過。
3. **建議存成 PNG**。JPEG 壓縮會讓顏色和邊緣模糊；可以用，但比對可能出現雜點。
4. **輪廓要封閉**：系統會自動補小缺口，補不起來的標成「輪廓未封閉」，請醫師重畫。
5. 可以畫輪廓線，也可以塗滿；同一批請維持同一種方式。
6. **筆畫寬度**：待確認輪廓線本身算在構造內或外（目前預設算在內）。
7. 不要在圖上寫字或畫其他記號；需要說明請寫在 `清單.csv` 的備註欄。

系統的處理方式（**比對差異法**）：
- 把傳回的圖和系統原本的影像逐像素比對，只取出醫師新加的筆畫。
- 依「顏色對照」分類成各構造，封閉輪廓自動填滿。
- 只取掃描扇形區內的差異，標頭、文字、量測區不會被誤認成筆畫。

**標籤 PNG**（用標註軟體輸出，例如 ITK-SNAP、CVAT、LabelMe）：
- 和原圖同尺寸的單通道 PNG。
- 數值：0 背景、1 腎實質、2 腎竇、3 肝、4 脾。
- 檔名同樣是影像 ID。

## 3. 圈選規則

### 3.1 腎臟外框（含腎竇）

- 外框沿腎被膜（腎臟外圍的高回音細線）的**外緣**畫（D48），開始前再請圈選醫師確認。計算皮質亮度時，程式略過最外層 1 mm。
- 不含腎周脂肪。
- 被肋骨陰影或腸氣遮住的部分：依兩側可見的邊緣自然連接。
- 腎臟被影像邊緣截斷：照可見範圍畫到影像邊緣。
- 囊腫：包含在腎臟外框內，並用「囊腫」項目另外圈出（D51）。

### 3.2 腎竇

- 中央的高回音區（脂肪、血管、集尿系統），連同腎盂。
- 有積水時，擴張的腎盂與腎盞也算腎竇。
- 腎竇與腎實質的分界不清楚時，以回音明顯變亮的位置為界。
- 皮髓質分界完全消失、分不出腎竇時：不畫腎竇，並告知（系統會把這張的腎竇設為「未標」）。

### 3.3 肝與脾（整個可見器官，決策 D19）

- 右腎影像圈肝，左腎影像圈脾。
- 圈**影像中看得到的整個器官**範圍，不是只畫一小塊參考區。
- 器官內的血管算在器官內；膽囊、腸道、肋骨陰影不算。
- 「同深度」不需要醫師處理：計算回音比時，程式只取和皮質同深度（上下 5 mm）的肝或脾像素。
- 畫面中沒有肝或脾：不畫，並依 §2.1 表示。

## 4. 回音分級規則（在系統內判讀）

### 4.1 定義

| Grade | 定義 |
|---|---|
| 0 | 腎皮質比參考器官**黑** |
| 1 | 腎皮質與參考器官**相近** |
| 2 | 腎皮質比參考器官**白** |
| 3 | 腎皮質明顯變白，**接近（或等於，待確認）**腎竇亮度 |

文獻依據：Hricak 等人 1982 年的分級（分級文字取自二手資料）；詳見[腎臟超音波影像判讀入門](Deep_research/reports/腎臟超音波影像判讀入門.md)。

### 4.2 判讀方式

1. 在系統「標註與回饋 › 回音分級」判讀，先選自己的名字（醫師名單）。
2. 一個項目是「一位病人的一側腎」，畫面會顯示該側所有影像。
3. 只比較**同深度**的皮質與參考器官；避開髓質錐體、囊腫、陰影。
4. 不調整顯示亮度或對比（系統固定顯示設定）。
5. 使用圈選網站時每張影像各給一個分級（D49），全部保留，回音分級模型逐張訓練；系統內的舊流程仍是每側一個。
6. 沒有參考器官，或影像不足以判斷時，選「無法判斷」並寫原因。

### 4.3 盲測

分級時不顯示：
- eGFR、病人臨床資料。
- 同一病人另一側或其他次檢查的分級。
- 任何 AI 結果、回音比值。

匯出給醫師圈選的影像也不含 eGFR、AI 結果或疊圖。

## 5. 側別與切面

- 側別由右下角體表示意圖自動判斷：有肚臍「×」為正面圖（探頭在畫面左邊＝右腎），有脊椎直線為背面圖（探頭在畫面左邊＝左腎）。真實影像沒有側別文字。
- 判斷不出來的（目前 975 張中 2 張）在「資料集」手動設定。
- 側別和畫面內容矛盾時（例如判為左腎、但畫面中是肝），以畫面內容為準並修正。
- **測試集每側 1 張的挑選規則**：同一位病人同一側的影像中，優先選長軸、技師量過腎長（Dist A）且腎長最長的那張；同分時取影像 ID 較小的。

## 6. 流程

| 步驟 | 內容 | 完成標準 |
|---|---|---|
| 1. 醫師確認 | 本文件「待確認」的項目、四種構造的顏色或表示方式 | 決定寫入決策紀錄 |
| 2. 測試集 | 建立測試集批次（每位測試病人每側 1 張，約 72 張）→ 匯出 → 醫師圈選 → 傳回 → 上傳 → 檢查 → 匯入 | 測試集完成度 100%；測試集影像永遠不進分割訓練 |
| 3. 第 1 批訓練影像 | 建立批次（約 100 張，依各折、eGFR 分組、機型、側別平均抽樣）→ 同上 | 全部匯入或退回重圈 |
| 4. 訓練分割 | 用目前所有醫師遮罩訓練分割模型 | 學習曲線多一個點 |
| 5. 下一批 | 重複 3–4，每批約 100 張，遮罩一直累積 | 連續兩輪交叉驗證 Dice 進步 < 0.01 時停止（通常總共約 250–300 張） |
| 6. 一致性 | 【已取消（D36）】傳回的圈選遮罩是多位醫師共同註記的結果，不另外請第二位醫師獨立圈選 | — |
| 7. 回音分級（選用） | 兩位醫師在系統內獨立分級；不一致的討論後定共識 | 保留兩人原始分級與共識；目前 0 筆 |

- 每批都會有匯出日期、傳回數、已匯入、需重圈的紀錄（系統「醫師圈選」與 `03_資料/09_索引/醫師圈選批次.csv`）。
- 被退回的影像會列入「需請醫師重圈」，下次匯出時可以一起給醫師。
