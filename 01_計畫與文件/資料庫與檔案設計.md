## 1. 資料庫

### 1.1 位置與分工

三個 SQLite 檔案都在 `03_資料/00_資料庫/`，使用 WAL 模式。

| 檔案 | 內容 | 遷移 |
|---|---|---|
| `system.sqlite3` | 系統：工作階段、背景工作、稽核、人員、設定、回收桶 | `migrations/system/versions/s0001_baseline.py` |
| `research.sqlite3` | 研究：批次、病人、影像、標註、切分、版本、訓練、模型、評估、醫師圈選、遮罩組 | `r0001_baseline.py`、`r0002_m2.py`、`r0003_m25.py`、`r0004_trash_runs.py`、`r0005_feedback.py`、`r0006_image_grades.py`、`r0007_trash_features.py` |
| `clinical.sqlite3` | 醫師端（M3）：病人、檢查、影像、分析、修改紀錄、報告與版本、接收 | `c0001_baseline.py`（空）、`c0002_m3.py`、`c0003_overrides.py` |

- 開啟方式：`app/db/session.py` 的 `session_scope('system'|'research'|'clinical')`。
- 啟動時自動執行遷移（`app/main.py` 的 `migrate_all`）。`s0001`、`r0001` 會用目前的模型 `create_all`，所以新資料庫一定有全部的表。`r0002` 以「有就略過」的方式補上 M2 新增的表與欄位，舊資料庫可以安全升級。
- 新增欄位的作法：寫新的遷移（例如 `r0003_*.py`），先 `create_all(checkfirst=True)`，再逐欄檢查、沒有才 `ALTER TABLE ADD COLUMN`。
- 時間欄位一律是 ISO 8601 字串（`app/core/ids.py` 的 `now_iso()`），`sessions` 例外使用浮點秒數。
- 刪除：研究資料用 `trashed_at` 欄位做軟刪除，並在 `trash_groups` 記一組（§1.2）；永久刪除才移除資料列與檔案（訓練、評估、模型資料夾，切分檔，資料集版本資料夾，遮罩 PNG），只刪物件自己的資料夾、不留下空資料夾，標準資料夾保留（M2.5 #109、#110）。

### 1.2 system.sqlite3【已實作】

#### `sessions`（本機工作階段）

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | 字串，主鍵 | 工作階段 ID |
| token_hash | 字串 | cookie token 的雜湊（不存原文） |
| csrf | 字串 | CSRF token（原文；只在本機） |
| boot_id | 字串 | 伺服器啟動 ID；重啟後舊工作階段全部失效 |
| created、expires、revoked | 浮點數 | 秒數時間戳 |

#### `jobs`（背景工作）

| 欄位 | 說明 |
|---|---|
| id | `JOB-{16 位十六進位}` |
| kind | 工作種類（見系統架構 §4.2） |
| target | 顯示用的對象說明，例如「全部影像」、訓練 ID |
| status | `queued`、`running`、`stopping`、`completed`、`failed`、`stopped`、`interrupted` |
| progress、message | 進度（0–1）與目前訊息 |
| config_json、result_json | 工作設定與結果 |
| error_code、error_message | 失敗原因 |
| stop_requested | 停止旗標（工作每秒檢查） |
| created_by、created_at、started_at、finished_at | 建立者與時間 |
| retry_of | 重試時指向原工作 |

#### `job_events`

工作事件：`id`、`job_id`、`type`（progress、log、data、metric…）、`data_json`、`created_at`。寫入有節流，不會每個 batch 都寫。刪除任務紀錄（`POST /api/jobs/delete`）時連同事件一起永久刪除。

#### `audit_log`（稽核）

`id`、`time`、`actor`（操作者）、`action`（中文動作名稱）、`target_type`、`target_id`、`detail_json`、`result`。

#### `people`（醫師與操作者名單）

`id`、`name`、`kind`（`physician` 或 `operator`）、`active`、`created_at`。
- 醫師名單用於：回音分級的判讀者、模型升為臨床時的核准醫師、M3 報告簽核（規劃）。
- M2.5 起，遮罩不再記錄醫師身分（醫師在系統外圈選），只記選填的「圈選者代號」（決策 D18）。

#### `settings`（系統設定）

`key`（主鍵）、`value_json`、`updated_at`。可用的鍵定義在 `app/services/settings_store.py` 的 `DEFAULTS`，不認識的鍵會被拒絕：

| 鍵 | 預設 | 說明 | 狀態 |
|---|---|---|---|
| `trash_retention_days` | 30 | 回收桶保留天數（1–365）。目前只儲存，尚未自動清除 | 【已實作】 |
| `residual_check` | true | 匯入後是否在去識別化影像上再跑一次 OCR，找個資殘留 | 【已實作】 |
| `primary_split_id` | 無 | 主切分：圈選批次、遮罩組、比較組、索引的「切分組別」預設使用；必須是存在的切分；沒設定時用最新的切分 | 【已實作】 |
| `circling_colors` | 空 | 顏色對照：`[{color: "#rrggbb", structure: kidney|sinus|liver|spleen}]`；同一顏色只能對應一個構造（由你在看過醫師的圖後設定） | 【已實作】 |
| `circling_color_tolerance` | 40 | 顏色比對的容許距離（RGB 歐氏距離，5–150） | 【已實作】 |
| `clinical_plan` | `{segmentation: null, egfr: null, grade: null}` | 醫師端分析方案：三區各一個模型 ID；只能選「臨床上線」或「候選」、任務要相符（`clinical/plan.py` 的 `validate`；D40、D41） | 【已實作】（M3 階段 A） |
| `clinical_receiver_port` | 8443 | 雙機展示的上傳連接埠（1024–65535，不能是 8000；D38） | 【已實作】（M3 階段 A） |
| `clinical_device_mode` | false | 超音波機器模式（D39）。階段 F 之前不能開啟（422） | 【已實作】（M3 階段 A） |

另外有一個內部使用的鍵 `patient_match_state`（病人對照的待確認狀態），不在 `DEFAULTS`，介面不顯示。

#### `trash_groups`（單一回收桶）

`id`（`TR-{16 位}`）、`kind`（split、dataset_version、mask、run）、`label`、`entries_json`（這組包含的物件）、`reason`、`created_by`、`created_at`、`state`（trashed、restored、purged）、`closed_at`。
- 一組可以包含多個物件，例如「重新產生草稿」或「依來源刪除草稿」時整批移入，可以一次還原。
- 支援的物件種類定義在 `app/trash/service.py` 的 `KINDS`：split、dataset_version、mask、run（訓練）、model（模型；只會跟著訓練一起移入，`entries_json` 同一組）。

### 1.3 research.sqlite3【已實作】

#### `batches`（匯入批次）

`id`（`B0000` 或 `B{YYYYMMDD}-{nn}`）、`source_kind`（original、inbox、clinical）、`source_label`、`status`、`created_by`、`created_at`、`finished_at`、`counts_json`（已匯入、待確認、重複略過等）、`job_id`。

#### `patients`（研究病人）

| 欄位 | 說明 |
|---|---|
| id | `P-{4 位數}` |
| source_ref | 病人表裡的列鍵，用來回填與重新比對（不含姓名、病歷號） |
| sex | `M`／`F` |
| age | 年齡 |
| has_diabetes | 是否有糖尿病 |
| egfr、egfr_date | eGFR 數值與日期。**API 不回傳 eGFR 數值，只回傳分組** |

- eGFR 分組（≥90、60–89、30–59、15–29、<15）由 `app/data/patients.py` 的 `EGFR_GROUPS` 計算，不存欄位。

#### `source_map`（原始檔對照，含個資路徑，受限）

`image_id`（主鍵）、`batch_id`、`original_relpath`。只在匯入、重新去識別化、病人對照時讀取；API 不回傳。

#### `images`（去識別化影像）

| 欄位 | 說明 |
|---|---|
| id | `IMG-{12 位十六進位}` |
| batch_id | 來自哪一批匯入 |
| sha256、phash | 內容雜湊與感知雜湊（匯入時找重複） |
| patient_id | 對到的研究病人；未對應時為空 |
| machine、template_id、width、height | 機型、版面範本、尺寸（去識別化影像與原始影像同尺寸） |
| side、side_source | 側別（right、left）與來源（bodymark、ocr、manual、circling＝醫師圈選網站，D52）；manual 與 circling 不會被重新去識別化或重新判斷側別蓋掉 |
| view | 切面（long、short、oblique） |
| pixel_spacing_mm、spacing_check | 像素間距與檢查結果（ok、ticks_only、ocr_only、mismatch、missing） |
| sonographer_length_mm、sonographer_width_mm | 技師量的腎長、腎寬（Dist A、Dist B） |
| ocr_age、ocr_sex | 標頭讀到的年齡、性別（只存解析後的值，不存原文） |
| scan_params_json | 掃描參數（增益等） |
| caliper_pixels | 量測游標的像素數 |

| review_reasons_json、exclude_reason | 待確認原因、排除原因 |
| deid_check | 去識別化殘留檢查結果 |
| created_at | |

#### `layout_templates`（版面範本）

`id`、`machine`、`width`、`height`（同機型同尺寸唯一）、`version`、`regions_json`（遮蓋區域）、`readers_json`（6 個讀取框：header、params、measure、side、ruler、bodymark）、`updated_at`、`updated_by`。

#### `mask_annotations`（遮罩）

分割訓練預設只用「已確認」的遮罩（訓練設定 `mask_policy=verified`；`any` 才會用草稿）。主切分測試集的影像不會產生任何草稿。

| 欄位 | 說明 |
|---|---|
| id | 整數 |
| image_id、version | 影像與版本（同一張影像的版本號遞增，所有來源共用） |
| annotator | 存檔者或草稿來源名稱 |
| relpath | 標籤 PNG 的相對路徑（0 背景、1 腎實質、2 腎竇、3 肝、4 脾） |
| shapes_json | 多邊形與筆刷形狀（系統內編輯器使用） |
| flags_json | 旗標：`labeled`（這份遮罩標了哪些構造，部分標註用）、`review`、`reasons`、腎竇與腎臟的檢查結果等 |
| status | `draft`、`done`、`reviewed`（草稿已接受）、`rejected` |
| reviewer | 保留欄位，目前未寫入 |
| source | `manual`、`legacy`、`medsam`、`rule`、`model`；M2.5 新增 `physician_upload`、`edited_upload` |
| verified_by、verified_at | 人工確認者與時間 |
| created_at、trashed_at | |

- 「已確認」的定義在 `app/data/versions.py` 的 `mask_verified`：人畫且完成，或有 `verified_by`。M2.5 起，醫師上傳的遮罩匯入時就算已確認。
- M2.5 起 `flags_json` 新增 `structures`：每個構造的狀態（drawn、absent、unlabeled），由它產生 `labeled`；另記 `circler`（圈選者代號）、`circling_item_id`。

#### `image_labels`（影像標籤）

`id`、`image_id`、`kind`、`value_json`、`annotator`、`created_at`；同一張影像 × 種類 × 標註者唯一。目前 kind 有 `side`（側別與切面）與 `quality`；**M2.5 移除 `quality`**，資料表保留給側別。

#### `grade_labels`（回音分級）

`id`、`patient_id`、`side`、`image_id`（判讀時主要看的那張，可空）、`grade`（0–3；空值表示無法判斷）、`unsure_reason`、`rater`（醫師名單中的醫師）、`is_consensus`（共識結果）、`created_at`。

#### `agreement_reports`（一致性報告）

`id`（`AGR-{16 位}`）、`kind`（目前固定 `all`）、`raters_json`、`metrics_json`（分級 kappa、遮罩 Dice）、`created_at`。

#### `clinical_feedback`（臨床回饋）

`id`、`exam_id`、`item`、`ai_value`、`doctor_value`、`by`、`created_at`、`decision`、`decided_by`、`decided_at`；M3（`r0005_feedback.py`）新增 `kind`（exclude／include／side／length／grade）、`side`、`image_id`（醫師端影像 CI-）、`reason`、`model_id`。醫師端檢查工作區的修改會寫入；不含年齡、糖尿病等臨床資料。

#### `dataset_versions`（凍結的資料集版本）

`id`（`dsv-{4 位數}`）、`note`、`image_count`、`patient_count`、`manifest_sha256`、`created_by`、`created_at`、`trashed_at`。內容在 `05_資料集版本/{id}/manifest.json`（§3.1）。

#### `splits`、`split_entries`（病人層級切分）

`splits`：`id`（`split-{4 位數}`）、`parent_id`（增量分配時指向原切分）、`method`、`seed`、`folds`、`test_ratio`、`stratify_by`（`egfr_group`）、`sha256`、`note`、`test_locked`（舊）、`test_locks_json`（M2.5）、`created_by`、`created_at`、`trashed_at`。

`split_entries`：`split_id`、`patient_id`、`group`（`fold-1`…`fold-k`、`test`、`prospective`）。

- 切分不綁資料集版本；訓練時才選擇「版本＋切分」。
- 測試鎖依任務各自鎖定（M2.5，決策 D27）：`test_locks_json` 記錄分割、eGFR、回音分級各自是否已評估過固定測試集；鎖住分割不影響 eGFR。M2 的 `test_locked` 是整個切分共用的鎖，現在只用來相容舊資料（§1.4）。

#### `training_runs`（訓練）

`id`（`RUN-{YYYYMMDD}-{nnn}`）、`task`（segmentation、egfr、grade；M2.5 移除 quality）、`name`、`experiment_id`、`split_id`、`dataset_version_id`、`config_json`、`status`（draft、queued、running、completed、failed、stopped、interrupted）、`job_id`、`summary_json`、`relpath`、`created_by`、`created_at`、`finished_at`、`trashed_at`。

各 epoch 的歷程不存資料庫，存在 `fold-k/history.csv`（§2.3）。nnU-Net 基準也是一筆 `training_runs`，`config_json` 含 `framework: nnunetv2`。

#### `models`（模型庫）

`id`（`{任務}/{名稱}@{版本}`）、`task`、`name`、`version`、`stage`（research、candidate、clinical、retired）、`run_id`、`relpath`、`manifest_json`、`stage_history_json`（每次變更階段的人、時間、核准醫師）、`created_by`、`created_at`、`trashed_at`（M2.5，`r0004`：跟著來源訓練移入回收桶）。架構、雜湊、模型卡都在 manifest 與 `model_card.md`。

#### `evaluations`（評估）

`id`（`EVAL-{YYYYMMDD}-{nnn}`）、`model_id`、`run_id`、`target`（`oof` 交叉驗證、`test` 固定測試集）、`metrics_json`、`relpath`、`created_by`、`created_at`。

#### `experiments`（實驗）

`id`（`EXP-{YYYYMMDD}-{nnn}`）、`name`、`template`（init、ablation、custom；M2.5 新增 `egfr_compare`）、`config_json`（任務、版本、切分、共同設定、特徵集）、`note`、`created_by`、`created_at`、`trashed_at`。訓練透過 `training_runs.experiment_id` 連回實驗。

#### `feature_sets`（特徵集）

`id`（`FS-{YYYYMMDD}-{nnn}`）、`spec_json`（來源、分割訓練、是否交叉擬合、皮質與深度參數）、`rows`、`relpath`、`job_id`、`status`、`created_by`、`created_at`、`trashed_at`（`r0007`：跟著分割訓練或遮罩組移入回收桶）。內容在 `04_模型產出/特徵/{id}/`。

## 2. 資料夾與檔案

> 2026-10-23 依實作企劃設計：支援多模型、多批次與持續收案。2026-10-29 依實際程式更新，並加入 M2.5 的整理。

### 2.1 設計原則

1. **依資料的生命階段分開**：原始 → 去識別化 → 人工標註 → 模型產出 → 凍結版本，每一階段一個資料夾，不混放。
2. **人做的和機器做的分開**：人工標註放 `03_人工標註`，模型預測放 `04_模型產出`。重新訓練不會覆蓋人工標註。
3. **模型產出依來源分開**：同一張影像可以有好幾個模型的預測，各自放在自己的資料夾，可以並存、互相比較。
4. **持續收案以批次為單位**：每次匯入是一個批次，有自己的封存、報表與紀錄。
5. **大量檔案分桶**：影像依 ID 第 5、6 碼（`IMG-` 之後兩碼）分到最多 256 個子資料夾（`app/core/ids.py` 的 `shard`）。
6. **分類存在資料庫**：病人、切分、標註狀態都在資料庫，檔案用 ID 命名，改分類不必搬檔案。M2.5 另產生不含個資的索引 CSV，方便直接在檔案總管查找（§2.5）。
7. **可以刪掉重建的集中放**：日誌、暫存、執行狀態放在 `08_系統`，備份時略過。
8. **受限區**：`IMG_original/` 與 `03_資料/01_原始封存/` 含個資，網頁不顯示、不提供「開啟資料夾」按鈕。

- 只收「可用且已對到病人」的影像。
- 每張影像記錄當時最新、未退回的遮罩版本（草稿也算）。
- 檔案在資料夾內，含 eGFR 數值，只供訓練程式讀取；API 不回傳 eGFR 數值。

### 3.2 切分 `06_資料切分/{id}.json`【已實作】

病人 → 組別的對照與雜湊。切分方法：依 eGFR 分組分層，每組依最大餘數法分配測試名額，其餘依序輪流分到各折（`app/data/splits.py`）。目前的 split-0001：seed 42、5 折、測試集 36 位病人（194 張）。

- 推論時檢查合約版本與檔案雜湊，不符就拒絕。

### 3.5 特徵集 `04_模型產出/特徵/{FS-ID}/`【已實作】

## 5. 持續收案流程【已實作】

1. 新收案影像和病人表放進 `06_匯入區/待匯入/{資料夾}`。
2. 在「資料集 › 匯入」選擇這個資料夾。系統先預覽：張數、機型、重複、缺少的病人資料。
3. 確認後執行匯入工作：
   - 原始檔**複製**到 `01_原始封存/{批次}`；
   - 去識別化影像寫入 `02_去識別化影像`；
   - 匯入報表寫入 `07_匯入紀錄`；
   - 完成後把匯入區的資料夾移到 `已完成/`。
4. 上傳病人表並執行對照；需要人工確認的在「病人」分頁處理。
5. 新病人在資料切分頁「新病人分到各折」或「新病人放前瞻集」，舊病人的組別完全不變。
6. M2.5 起：新影像成為醫師圈選批次的候選（不會自動匯出）。
7. 凍結新的資料集版本，再開始訓練。

醫師端轉入研究（已簽核的檢查以「臨床」批次匯入）是 M3 規劃，尚未實作。
